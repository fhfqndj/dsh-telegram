## [1.0.0] — 2026-11-21

Релиз для npm: установка одной командой, приватность лога, вопросы и подтверждения в чате.

### Добавлено

- Пакет `dsh-telegram-connect` с bin `dsh-telegram-connect`: `install`, `uninstall`, `status`.
- `/doctor` — диагностика бота и моста; `/model` — пикер модели; `/cost` — расход токенов.
- Вопросы агента (`ask_user_question`) в чат кнопками и текстом; approvals кнопками.
- Политика подтверждений: `ask` / `trusted` / `yolo`.
- Allowlist и pairing-код (`/pair`).
- `/unbind [id|all]`, `/mute` и `/unmute`, `/steer <текст>`.
- Строка статуса в карточке прогресса: «Вызываю bash», «Жду подтверждения».
- Отправка файлов агентом (`telegram_send`), приём фото и документов из чата.
- Ретенция: расход и модели старше `retentionDays`, чистка мёртвых биндингов.

### Изменено

- Тексты бота, панели и README без эмодзи; тест-страж `test/i18n.test.js`.
- Монолит `index.js` разрезан на модули: `src/config.js` и восемь миксинов в `src/bridge`
  (ядро, доступ, сессии, доставка, команды, seam-обработчики, модель, расход); 300 строк в точке входа.
- ACL: адрес инициативных сообщений назначает только владелец; `/use` и `/peek` — только владелец;
  кнопки доступны участникам allowlist.
- Состояние переживает рестарт (usage, model, mute), запись в файл троттлится, токен кэшируется.
- Комментарии вычищены по навыку `comment-cleanup`: остались только объяснения «почему».
- Панель разбита на секции: Подключение, Доступ, Уведомления, Подтверждения, Рабочее пространство;
  единые состояния полей, один компонент уведомлений, пустые состояния, доступность и узкое окно.
- Логи без текстов задач: по умолчанию только длина сообщения; `/log` доступен владельцу.
- Ворота версии хоста: без `sessionController`/`credentials` плагин пишет причину и не запускается.
- Ответы уходят rich-сообщением: нативные таблицы, пустая строка между блоками, переносы абзацев.

## [0.1.0] — 2026-11-20

Первая рабочая версия: бот внутри DSH Desktop.

### Добавлено

- Long polling Bot API с дедупом апдейтов и устойчивостью к 409/429/401.
- Привязка владельца по `from.id` только из приватного чата.
- Задачи из чата уходят в активную сессию DSH; `/new` создаёт сессию внутри
  зарегистрированного workspace.
- Команды `/start`, `/help`, `/status`, `/sessions`, `/use`, `/new`, `/peek`,
  `/stop`, `/quiet`, `/notify`, `/lang`, `/log`.
- Стриминг ответа карточкой прогресса; финал — отдельным сообщением.
- Rich-сообщения Bot API 10.1 с гибкой настройкой: мастер-выключатель, нативные таблицы,
  заголовки как заголовки (по умолчанию жирным).
- Авто-фолбэк на HTML, если сервер rich не поддерживает:
  таблицы выравниваются моноширинным блоком.
- Уведомления по чату: без `/notify on` в чат ничего не приходит.
- Файловый лог `$DSH_HOME/logs/telegram.log` и команда `/log`.
- Двуязычные ответы: `ru` и `en`, выбор по языку клиента или вручную.
- Подтверждения инструментов кнопками в Telegram (allowed-once, таймаут → отказ).
- Приём фото (в промпт картинкой) и документов (в `<workspace>/.telegram-inbox`).
- Отправка файлов агентом: инструмент `telegram_send` (текст и/или документ, до 50 МБ).
- `/model` — пикер модели из каталога DSH: кнопки `provider/model` или `/model provider/model`;
  текущая модель помечается ✓ и показывается в `/status`.
- `/cost` — расход токенов по сессии и суммарно (`inputTokens`, `outputTokens`, кэш, reasoning,
  число запросов); строка токенов добавлена в `/status`.
- Политика подтверждений: посттуры `ask` / `trusted` / `yolo`, списки «разрешать без вопроса»
  и «запрещать сразу» (шаблоны `*`). Запрет срабатывает раньше вопроса.
- Вопросы агента (`ask_user_question`) приходят в чат карточкой с кнопками вариантов или
  принимаются свободным текстом; таймаут 10 минут пропускает вопрос. Выключается полем
  «Вопросы агента».
- Allowlist: список user id, каждому — свой чат, сессия и уведомления; команда `/doctor`.
- Меню команд перезаписывает default scope и ставит chat-scope на чат владельца: старый
  список другого бота больше не показывается.
- Таблицы без нативной поддержки рендерятся списком («• Колонка: значение»), а не код-блоком.
- Финалы уходят rich-сообщением (markdown): между блоками — пустая строка, каждый абзац
  начинается с новой строки (жёсткий перенос двумя пробелами, `hardLineBreaks`). Таблицы,
  списки и код не трогаются. При отказе сервера — обычный HTML.
- Панель Telegram в боковой колонке DSH: токен, владелец, workspace,
  режим уведомлений, rich, язык, диагностика.

### Исправлено по ходу разработки

- Клиентский модуль не объявлял `inject: remote.credentials`.
- Сессии создавались с голым `cwd` и попадали в Desktop вне группы workspace.
- Финал отправлялся на каждый шаг хода, а не на `turn/end`.
- Падение обработчика события валило Host: теперь ошибки изолированы и пишутся в лог.
- `workspacePath` при пустом конфиге уходил в рекурсию.
- Список сессий мог показать сессии чужих workspace.
- «Ядовитый» апдейт превращал поллер в busy-loop.
- Карточка рвала HTML при длинном ответе; пустой финал оставлял карточку в чате (теперь режется
  по границе тегов, карточка удаляется).
- Первый `/start` делал владельцем любого, кто нашёл бота: теперь без `ownerId` бот отказывает.
- У всех вызовов Bot API появился таймаут; состояние и лог пишутся с правами `0600`.
